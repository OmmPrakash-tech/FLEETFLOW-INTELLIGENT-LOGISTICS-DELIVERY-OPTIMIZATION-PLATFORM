# Executed verification

Verification performed on 16 September 2026 using the existing local checkout and native PostgreSQL 18.3.

## Passed

- Baseline: the original Spring Boot context test passed before feature implementation.
- Backend `verify`: 20 tests, zero failures, zero errors, zero skipped; executable Spring Boot JAR built.
- Algorithms: state rules, known Haversine distance, ETA input handling, indirect shortest paths, unreachable paths, capacity filters and deterministic multi-stop visits.
- PostgreSQL integration: final-stock contention, concurrent duplicate order requests, competing driver assignment, stock release, delivery deduction, concurrent duplicate delivery events, failure/return handling and ownership enforcement.
- Account security: password-reset hashing and single use, refresh rotation, concurrent refresh single winner, logout revocation.
- HTTP workflow: register → login → create catalog/warehouse/stock/fleet → create customer order → pack → assign → report driver location and update ETA → receive SSE → dispatch → deliver → inventory deduction → analytics → audit → logout. Cross-customer reads, unauthorized writes, invalid transitions and fractional quantities are rejected. Completed shipments no longer expose driver coordinates.
- Redis outage fallback: a simulated Redis failure returns the correct calculated distance and opens the retry circuit. Assignment also works on this machine without Redis available.
- Frontend production build: TypeScript and Vite pass. Chart code is split into a separate chunk.
- Playwright: two Chrome tests pass for the admin dashboard/order/tracking flow and mobile customer navigation/order form. No desktop page exceptions were captured. Mobile viewport has no horizontal page overflow.
- Compose configuration validates successfully.
- GitHub Actions completed successfully for commit f5f401b (backend and frontend verification).
- Secret scan found no local DB password, signing key or demo password in tracked/candidate source files; `.env` is ignored.

The backend tests create/drop a dedicated random test schema. The development schema and seeded data are separate.

## Not verified / blocked

- **Docker runtime:** Docker Desktop fails before starting its Linux engine. Its local log reports: `initializing Ingest server ... sailor-ingest.sock ... The file cannot be accessed by the system`. The engine pipe is unavailable. No factory reset or deletion of Docker data was performed. Consequently container image builds, container integration and Testcontainers were not run.
- **Real SMTP delivery:** no SMTP service/credentials were supplied. The password-recovery lifecycle is tested with a mocked delivery adapter; real mail delivery is not claimed.
- **Live Redis cache hits:** no running native Redis was found and Docker is unavailable. Failure fallback is tested; a live Redis deployment remains to be verified.
- **Database outage:** the error mapping is implemented, but the shared native PostgreSQL service was not stopped to induce an outage.
- **Load and security audits:** no benchmark, sustained load test or independent penetration test was run. No performance figures are claimed.
- **Cloud deployment:** not requested and not performed.

## Data interpretation

The initial seeded dashboard contains six real demo orders and two completed deliveries. Their timestamps were generated by the service during seeding; there is no fabricated historical trend or delivery-duration benchmark. Numbers may change as users exercise the application.
