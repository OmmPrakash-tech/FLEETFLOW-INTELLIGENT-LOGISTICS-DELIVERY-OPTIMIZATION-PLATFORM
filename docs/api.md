# API guide

Interactive OpenAPI: `/swagger-ui.html`; JSON: `/v3/api-docs`. Use the Swagger Authorize control with an access token. Authentication endpoints are public except `me`, `logout` and `password`. All logistics endpoints require a JWT and enforce roles and/or ownership.

## Identity

| Method | Path | Behavior |
| --- | --- | --- |
| POST | /api/auth/register | name, email, password → CUSTOMER session |
| POST | /api/auth/login | email, password → session |
| POST | /api/auth/refresh | token → rotated refresh and access tokens |
| GET | /api/auth/me | Current public account projection |
| POST | /api/auth/logout | Revoke all sessions for current account |
| POST | /api/auth/password | currentPassword, newPassword; revokes sessions |
| POST | /api/auth/forgot-password | email; SMTP reset delivery when configured |
| POST | /api/auth/reset-password | token, password; single-use reset |

Access tokens expire in 15 minutes. Refresh tokens expire in seven days and rotate on every use. The `token` field is the refresh token, not the access JWT.

| Audit | GET /api/audit (admin) | Generated by business operations |

List APIs return arrays. Most lists support zero-based `page` and `size` (1–100, default 25). Orders support `status`, `search` over ID/address and `sort` of newest/oldest/priority. Products support name/SKU search. Addresses return all records belonging to the authenticated user.

## Order example

```http
POST /api/orders
Authorization: Bearer <access-token>
Idempotency-Key: order-checkout-unique-key
Content-Type: application/json

{
  "address": "Delivery address",
  "latitude": 20.3,
  "longitude": 85.8,
  "priority": 2,
  "slaHours": 24,
  "items": [{"productId": "<product-uuid>", "quantity": 2}]
}
```

Creation atomically moves through CREATED, CONFIRMED and ALLOCATING to WAREHOUSE_ASSIGNED. Its response is `{ "id": "..." }`. Failed allocation rolls back the order. A staff-created order belongs to that staff user; creating orders on behalf of arbitrary customers is not supported.

Next operations: PICKING → PACKED → assign → DISPATCHED → IN_TRANSIT → OUT_FOR_DELIVERY → DELIVERED. Transition body: `{ "status": "PICKING" }`. Customers can cancel before dispatch or request return after delivery. Assigned drivers can progress the delivery leg or mark it failed. Operators finalize returns.

## Retry contract

`Idempotency-Key` is required for order creation, stock receipt, assignment and transitions. Use 8–100 ASCII letters, digits, `.`, `_`, `:`, or `-`. Reuse the same key only for the same payload and operation. The key is scoped to the authenticated actor. A different payload produces 409 `IDEMPOTENCY_MISMATCH`. For multi-item orders, preserve line ordering on retries because the fingerprint uses the validated request representation.

## Errors

Service/controller errors include timestamp, HTTP status, code, message and request path. Security-filter errors contain status, code and message. No stack traces or SQL details are exposed. Typical statuses: 400 invalid input, 401 missing/invalid/revoked auth, 403 forbidden or forced password change, 404 missing record, 409 business conflict, 429 rate limit, 503 database/email/tracking capacity failure.

## SSE

The stream requires an Authorization header. The frontend uses authenticated fetch streaming because native EventSource does not support that header. `tracking` events carry the authorized shipment snapshot and event history. The endpoint sends heartbeat comments when unchanged. Connections close at one minute and the frontend reauthenticates and reconnects. Stream cursors/replay are not implemented; reconnect returns the latest snapshot including the persisted timeline.
